# 学園祭用Webアプリ

学園祭の各店舗・企画を回ってスタンプを集め、3×3 のビンゴを完成させるスマートフォン向け Web アプリです。

---

## 機能一覧

### スタンプラリー / ビンゴ
- 各店舗に置いてある NFC タグ(または QR コード)を読み込むとスタンプを取得できる
- スタンプは 3×3 のビンゴカードに反映される
  - 中央のマスは「Codeflow」で固定
  - 残り 8 マスは「飲食(food)」4 マス・「企画(activity)」4 マスがユーザーごとにランダム配置
  - スタンプを取ったスポットの種別に応じて、同じ種別のマスが 1 つ埋まる
- 縦・横・斜めの計 8 ラインでビンゴを判定し、達成ライン数・全マス制覇を表示
- 同じスポットのスタンプは 1 回しか取得できない
- ビンゴが揃ったらサークルの教室まで来てもらい、景品と交換する

### ユーザー管理
- ホーム(またはビンゴ画面)の「スタート」ボタンでユーザー ID を発行する
- ID はサーバーが HttpOnly Cookie(`stamp_rally_uid`、有効期限 30 日)で発行し、ログインは不要
- 発行済みの Cookie があれば同じ ID を使い続けるため、何度スタートを押しても進捗は消えない
- 発行できるユーザー数には上限がある(既定 10,000、超えると 503 を返す)

### 画面構成(フロントエンド)
| 画面 | 内容 |
|---|---|
| ホーム | スタートボタン、各画面へのショートカット |
| ビンゴ | ビンゴカード・進捗表示 |
| 読み込み | カメラで QR コード、Web NFC で NFC タグ(Android の Chrome のみ)を読み込んでスタンプ取得 |
| 景品 | 景品交換場所の案内 |
| 遊び方 | 遊び方の説明 |

`/mock` 以下にアクセスすると、API を使わないモック画面を表示できます。

### 管理画面(`/admin`)
運営用の画面です。来場者の画面からはリンクしていません。使い方は下の「管理画面」を参照。

| ページ | 内容 |
|---|---|
| 概要 | はじめた人・スタンプ総数・ビンゴ達成・全マス制覇の数、時間帯ごとのスタンプ数、埋まったマスの数ごとの人数、ユーザー数の上限 |
| CodeFlow | スタッフごとの回数(ランキング)、1 回ずつの記録(スタッフで絞り込み) |
| スポット | スポットごとのスタンプ数(人気順) |
| QR・URL | スポット・スタッフごとの QR コードと URL(コピー・SVG 保存・印刷) |

### 今後の予定
- 景品交換後のリセット(再度遊べるようにする)

| 項目 | 内容 |

データベースは使用せず、データはサーバーのメモリ上に保持しています。**サーバーを再起動するとスタンプ・ユーザーはすべてリセットされます。**

## API 一覧

すべて `/api` 以下。🔒 は Cookie のユーザー ID が必要(無い・無効な場合は 401)。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/spots` | スポット一覧を取得 |
| POST | `/api/users` | ユーザー ID を発行し Cookie に保存 |
| POST 🔒 | `/api/stamps` | スポット ID を指定してスタンプ取得 (`{"spot_id": 1}`) |
| POST 🔒 | `/api/stamps/nfc` | NFC タグの UID でスタンプ取得 (`{"nfc_uid": "04:AB:CD:EF:02"}`)。今の画面では使わない(タグの URL を読んで `/api/stamps/qr` に送る) |
| POST 🔒 | `/api/stamps/qr` | QR コードのトークンでスタンプ取得 (`{"qr_token": "..."}`) |
| GET 🔒 | `/api/stamps` | 取得済みスタンプ一覧 |
| GET 🔒 | `/api/bingo` | ビンゴの盤面・達成状況 |
| GET 🔑 | `/api/admin/summary` | 参加者数・ビンゴ達成数・スポットごと・時間帯ごとのスタンプ数などの概要(管理用) |
| GET 🔑 | `/api/admin/staff-stamps` | CodeFlow のスタンプをどのスタッフが押したかの記録・スタッフごとの数(管理用) |
| GET 🔑 | `/api/admin/links` | QR コード・NFC タグに書き込むトークン(スポット・スタッフごと。管理用) |

🔑 は管理用 API。環境変数 `ADMIN_PASSWORD` を設定したときだけ有効で、Basic 認証(ユーザー名 `admin`、パスワードは `ADMIN_PASSWORD`)がかかります。ふだんは管理画面(`/admin`)から使います。有効かどうかはサーバーの起動時にログに出ます(`admin API is enabled` / `admin API is disabled ...`)。

## スポット・NFC タグの登録

- スポット(店舗)は [model.go](go_backend/go_back/model/model.go) の `Spots` に定義します
- NFC タグの UID とスポットの対応は [map.go](go_backend/go_back/model/map.go) に登録します(`POST /api/stamps/nfc` 用。今の画面はタグに書いた URL を読むので、UID の登録はいりません)
- CodeFlow のスタッフ別トークン(と、スタッフのタグの UID)は [staff.go](go_backend/go_back/model/staff.go) に登録します(下の「CodeFlow のスタッフ別 URL」を参照)
- 起動時に [validate.go](go_backend/go_back/model/validate.go) が ID や QR トークンの重複、ビンゴに必要なスポット数などをチェックし、問題があれば起動を止めます(UID 未登録のスポットは警告のみ)

## 環境変数(バックエンド)

| 変数名 | 内容 | 既定値 |
|---|---|---|
| `MAX_USERS` | 発行できるユーザー数の上限 | 10000 |
| `COOKIE_SECURE` | Cookie の Secure 属性。`true` / `false` で固定、未設定ならリクエストが HTTPS かどうかで判定 | 未設定 |
| `ADMIN_PASSWORD` | 管理用 API のパスワード。未設定・16 文字未満なら管理用 API は無効 | 未設定 |

本番(HTTPS)では `COOKIE_SECURE=true` の設定を推奨します。
`ADMIN_PASSWORD` はリポジトリに書かず、Render のサービス(stamp-rally)の Environment で設定します。環境変数は起動時にしか読まないので、保存は「Save and deploy」で行います(再起動になるので、メモリ上の記録は消えます)。

## 管理画面
1. サーバーに `ADMIN_PASSWORD`(16 文字以上)を設定する(上の「環境変数」を参照)
2. `https://<ドメイン>/admin` を開き、`ADMIN_PASSWORD` のパスワードでログインする(このタブを閉じるまでログインしたまま)

- 数は 30 秒ごとに自動で更新されます(画面が見えている間だけ。「自動更新」で止められる)。「更新」ですぐに取り直せます
- 記録はサーバーのメモリ上にあるので、再起動(デプロイ・環境変数の変更)で消えます。管理画面を開いている間に再起動されたときは、画面で知らせます。残しておきたい記録は、再起動の前に CodeFlow・スポットのページから CSV で保存してください
- QR・URL のページでは、いま開いているドメインの URL が出ます。タグ・QR に使うときは本番の URL で開いてください(手元の環境で開くと注意が出ます)。「QRコードを印刷する」で、QR コードだけを A4 に 3 列で印刷できます
- QR・URL のページの URL を知っていれば、会場に来なくてもスタンプが取れます。画面を人に見せないでください

## 実行方法
### バックエンド
go をインストール
``` cmd
scoop install go
```

go_backend/go_back ディレクトリに移動して、以下のコマンドを実行(ポート 8080 で起動)
``` cmd
go run main.go
```

### フロントエンド
nodejs をインストール
``` cmd
scoop install nodejs
```

stamp_rally_front ディレクトリに移動して、以下のコマンドを実行
``` cmd
npm install
npm run dev
```

開発サーバーは自己署名証明書の HTTPS で起動する。スマホ(同じ Wi-Fi)からは `https://<PCのIP>:5173` で開き、証明書の警告を許可して進む。

## NFCタグ・QRコードの準備
NFCタグと QR コードには、どちらも次の URL を入れる(`<トークン>` は `go_back/model/model.go` の Spots にある、そのスポットの `QrToken`。CodeFlow だけはスタッフごとのトークンを使う。下の「CodeFlow のスタッフ別 URL」を参照)。
```
https://<ドメイン>/?spot=<トークン>
```
- iPhone のブラウザはページから NFC を読めないが、タグに URL が書かれていれば OS が読み取って通知を出し、タップすると Safari で開く(iPhone XS 以降)。Android も同様に開く
- QR コードは標準のカメラアプリで読み取って開く
- アプリの読み込み画面(ビンゴの「QR・NFC読込」、かぼちゃのメニューの「読込」)でも読める。QR コードはカメラで、NFC タグは Web NFC(Android の Chrome のみ)でタグの URL を読む
- どの読み方でも、アプリは URL のトークンを `POST /api/stamps/qr` に送ってスタンプを付ける(URL のドメインは確かめない)

NFCタグ(NTAG213 など)への書き込み手順
1. 「NFC Tools」アプリ(iPhone / Android)の「書く」→「レコードを追加」→「URL/URI」で上の URL を書き込む
2. スマホで読み取ってスタンプが付くことを確認する
3. 確認できたら同じアプリでタグをロックする(ロックしないと来場者に書き換えられる。ロックは取り消せない)

注意
- URL のドメインは本番のものにする。ドメインが決まってから書き込むこと
- トークンは推測されないようランダムな文字列にする(16文字未満・重複・空は起動時にエラーで止まる)。スポットを追加するときは次のコマンドで生成する
  ``` cmd
  node -e "console.log(require('crypto').randomBytes(16).toString('base64url'))"
  ```
- トークンを知っていれば現地に行かなくてもスタンプが取れるため、リポジトリは非公開にしておくこと
- トークンを変えると、そのスポットのタグ・QR は書き直しになる
- 通知から開いたブラウザと、スタートしたブラウザが違うと Cookie が別になり、スタートし直しになる(iPhone は Safari で遊ぶよう案内する)

### CodeFlow のスタッフ別 URL
CodeFlow(ビンゴ中央のマス)のスタンプは、誰が押したか(QR・NFCタグを出したスタッフ)を記録するため、スタッフごとに別のトークンを使う。
URL の形はほかのスポットと同じ `https://<ドメイン>/?spot=<トークン>` で、`<トークン>` に [staff.go](go_backend/go_back/model/staff.go) の `staffTokens` にある、そのスタッフの `QrToken` を入れる。

- CodeFlow にはスポット共通のトークンが無く、スタッフのトークンでしか取れない(共通のトークンや map.go の UID を CodeFlow に登録すると起動時にエラーになる)
- スタッフを追加するときは `staffTokens` に 1 行足し、トークンは上と同じコマンドで生成する。スタッフ名は重複不可
- アプリの読み込み画面もタグの URL を読むので、`NfcUID`(タグの UID)の登録はいらない(`POST /api/stamps/nfc` 用)
- スタッフ名は記録の表示に使うだけなので、あとから変えてもよい。トークンを変えるとそのスタッフのタグ・QR は書き直しになる

スタッフごとのスタンプ画像
- ビンゴの CodeFlow のマスには、押したスタッフの画像が出る(ほかのマスはかぼちゃ)
- 画像は [stamp_rally_front/public/stamps/](stamp_rally_front/public/stamps/) に置き、そのファイル名を `staffTokens` の `StampImage` に書く。ファイル名は英数字・`-`・`_` と拡張子(png・jpg・jpeg・webp・gif・svg)だけ(それ以外は起動時にエラー)
- `StampImage` が空のスタッフ・画像を読み込めなかったときは、ほかのマスと同じかぼちゃが出る
- 今入っている `staff1.svg`〜`staff3.svg` は仮の画像。画像は 1:1 の正方形で作るとマスにきれいに収まる

記録の確認
- 管理画面:`https://<ドメイン>/admin` の「CodeFlow」のページに、スタッフごとの回数と 1 回ずつの記録が出る(上の「管理画面」を参照)。「不明(手動 API)」は、手動 API(`POST /api/stamps`)で取ったスタッフ不明のもの
- 管理用 API:`https://<ドメイン>/api/admin/staff-stamps` をブラウザで直接開いても、ユーザー名 `admin` とパスワードを入れれば JSON で見られる。`counts` がスタッフごとの数、`stamps` が 1 回ずつの記録(新しい順)
- サーバーログ:スタンプが押されるたびに `staff stamp: spot=1(コードフロー) staff="..."` が出る。メモリ上の記録はサーバーを再起動すると消えるが、ログは Render のダッシュボード(Logs)に残る

ブラウザで http://localhost:5173 を開きます。`/api` へのリクエストは Vite の開発サーバーがバックエンド(localhost:8080)へプロキシします。

> アプリ内の NFC 読み込みは Web NFC(Android 版 Chrome など)に対応した端末・ブラウザでのみ動作します。カメラでの QR 読み込みと Web NFC は HTTPS(または localhost)でのみ動作します。
