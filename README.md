# 学園祭用Webアプリ

学園祭の各店舗・企画を回ってスタンプを集め、3×3 のビンゴを完成させるスマートフォン向け Web アプリです。

---

## 機能一覧

### スタンプラリー / ビンゴ
- 各店舗に置いてある NFC タグ(または QR コード)を読み込むとスタンプを取得できる
- スタンプは 3×3 のビンゴカードに反映される
  - 中央のマスは「Codeflow」で固定
  - 残り 8 マスは「飲食(food)」4 マス・「企画(activity)」4 マスがユーザーごとにランダム配置
  - スタンプを取ったスポットの種別に応じて、同じ種別のマスが 1 つ埋まる
- 縦・横・斜めの計 8 ラインでビンゴを判定し、達成ライン数・全マス制覇を表示
- 同じスポットのスタンプは 1 回しか取得できない
- ビンゴが揃ったらサークルの教室まで来てもらい、景品と交換する

### ユーザー管理
- ホーム(またはビンゴ画面)の「スタート」ボタンでユーザー ID を発行する
- ID はサーバーが HttpOnly Cookie(`stamp_rally_uid`、有効期限 30 日)で発行し、ログインは不要
- 発行済みの Cookie があれば同じ ID を使い続けるため、何度スタートを押しても進捗は消えない
- 発行できるユーザー数には上限がある(既定 10,000、超えると 503 を返す)

### 画面構成(フロントエンド)
| 画面 | 内容 |
|---|---|
| ホーム | スタートボタン、各画面へのショートカット |
| ビンゴ | ビンゴカード・進捗表示、NFC 読み込み(Web NFC 対応端末のみ) |
| QR | QR コード読み込み画面(※ 現在は UI のみ) |
| 景品 | 景品交換場所の案内 |
| 遊び方 | 遊び方の説明 |

`/mock` 以下にアクセスすると、API を使わないモック画面を表示できます。

### 今後の予定
- QR コード読み込みのフロントエンド実装(バックエンドの API は実装済み)
- 景品交換後のリセット(再度遊べるようにする)
- マップ:どの階のどの場所でどのクラス/サークルが何を運営しているかを視覚的に表示

データベースは使用せず、データはサーバーのメモリ上に保持しています。**サーバーを再起動するとスタンプ・ユーザーはすべてリセットされます。**

## API 一覧

すべて `/api` 以下。🔒 は Cookie のユーザー ID が必要(無い・無効な場合は 401)。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/spots` | スポット一覧を取得 |
| POST | `/api/users` | ユーザー ID を発行し Cookie に保存 |
| POST 🔒 | `/api/stamps` | スポット ID を指定してスタンプ取得 (`{"spot_id": 1}`) |
| POST 🔒 | `/api/stamps/nfc` | NFC タグの UID でスタンプ取得 (`{"nfc_uid": "04:AB:CD:EF:01"}`) |
| POST 🔒 | `/api/stamps/qr` | QR コードのトークンでスタンプ取得 (`{"qr_token": "..."}`) |
| GET 🔒 | `/api/stamps` | 取得済みスタンプ一覧 |
| GET 🔒 | `/api/bingo` | ビンゴの盤面・達成状況 |

## スポット・NFC タグの登録

- スポット(店舗)は [model.go](go_backend/go_back/model/model.go) の `Spots` に定義します
- NFC タグの UID とスポットの対応は [map.go](go_backend/go_back/model/map.go) に登録します
- 起動時に [validate.go](go_backend/go_back/model/validate.go) が ID や QR トークンの重複、ビンゴに必要なスポット数などをチェックし、問題があれば起動を止めます(UID 未登録のスポットは警告のみ)

## 環境変数(バックエンド)

| 変数名 | 内容 | 既定値 |
|---|---|---|
| `MAX_USERS` | 発行できるユーザー数の上限 | 10000 |
| `COOKIE_SECURE` | Cookie の Secure 属性。`true` / `false` で固定、未設定ならリクエストが HTTPS かどうかで判定 | 未設定 |

本番(HTTPS)では `COOKIE_SECURE=true` の設定を推奨します。

## 実行方法
### バックエンド
go をインストール
``` cmd
scoop install go
```

go_backend/go_back ディレクトリに移動して、以下のコマンドを実行(ポート 8080 で起動)
``` cmd
go run main.go
```

### フロントエンド
nodejs をインストール
``` cmd
scoop install nodejs
```

stamp_rally_front ディレクトリに移動して、以下のコマンドを実行
``` cmd
npm install
npm run dev
```

開発サーバーは自己署名証明書の HTTPS で起動する。スマホ(同じ Wi-Fi)からは `https://<PCのIP>:5173` で開き、証明書の警告を許可して進む。

## NFCタグ・QRコードの準備
NFCタグと QR コードには、どちらも次の URL を入れる(`<トークン>` は `go_back/model/model.go` の Spots にある、そのスポットの `QrToken`)。
```
https://<ドメイン>/?spot=<トークン>
```
- iPhone のブラウザはページから NFC を読めないが、タグに URL が書かれていれば OS が読み取って通知を出し、タップすると Safari で開く(iPhone XS 以降)。Android も同様に開く
- QR コードは標準のカメラアプリで読み取って開く
- アプリは URL のトークンを `POST /api/stamps/qr` に送ってスタンプを付ける

NFCタグ(NTAG213 など)への書き込み手順
1. 「NFC Tools」アプリ(iPhone / Android)の「書く」→「レコードを追加」→「URL/URI」で上の URL を書き込む
2. スマホで読み取ってスタンプが付くことを確認する
3. 確認できたら同じアプリでタグをロックする(ロックしないと来場者に書き換えられる。ロックは取り消せない)

注意
- URL のドメインは本番のものにする。ドメインが決まってから書き込むこと
- トークンは推測されないようランダムな文字列にする(16文字未満・重複・空は起動時にエラーで止まる)。スポットを追加するときは次のコマンドで生成する
  ``` cmd
  node -e "console.log(require('crypto').randomBytes(16).toString('base64url'))"
  ```
- トークンを知っていれば現地に行かなくてもスタンプが取れるため、リポジトリは非公開にしておくこと
- トークンを変えると、そのスポットのタグ・QR は書き直しになる
- 通知から開いたブラウザと、スタートしたブラウザが違うと Cookie が別になり、スタートし直しになる(iPhone は Safari で遊ぶよう案内する)

ブラウザで http://localhost:5173 を開きます。`/api` へのリクエストは Vite の開発サーバーがバックエンド(localhost:8080)へプロキシします。

> NFC 読み込みは Web NFC(Android 版 Chrome など)に対応した端末・ブラウザでのみ動作します。
