# 景品一覧画面 設計書

作成日: 2026-10-25  
開発ブランチ: `feature/prize-list`  
状態: 実装済み。下の「確認項目・受け入れ条件」はブラウザで確認済み

## 目的と合意事項

学園祭で用意する景品を、参加者が写真・名前・紹介文で確認できる画面を追加する。
既存の「景品」画面は、スタッフがビンゴ達成状況を一目で確認するための画面として残す。
一覧は別画面とし、景品画面内の「景品一覧を見る」ボタンから移動する。

- 未達成時は「ビンゴカードを見る」ボタンの下に入口を追加する。
- 達成済みの景品画面にも同じ入口を設ける。
- 一覧からは「景品画面に戻る」で元の景品画面に戻る。
- 一覧を見るためのビンゴ達成条件は設けない。
- 景品交換の操作、交換済み管理、在庫管理、景品選択・予約は追加しない。
- 画面下の常設タブや、かぼちゃメニューの新しい項目は追加しない。
- 既存のレイアウトとUIに厳密に準拠する。実装者の判断で独自のUIを導入しない。
- 景品ごとに画像を添付し、一覧に表示できるようにする。

## 現在の構成

`src/main.jsx` が通常の入口で `src/redesign/RedesignApp.jsx` を表示する。
画面切り替えは `currentScreen` と `navigate(screenName)` で行っており、各画面に個別のURLはない。
かぼちゃメニューとビンゴ画面の「景品」ボタンは、既存の `prize` 画面を開く。

`src/redesign/Prize.jsx` は `/api/bingo` を取得し、`bingo_count > 0` で達成を判断する。
未スタート（401）は未達成として扱い、読み込み中と通信エラーには専用の表示がある。
達成済みでは402教室への案内と、スタッフに画面を見せる説明を表示する。

以下のパスは、特記がなければ `stamp_rally_front/` からの相対パス。

## 画面遷移

```text
ビンゴ画面／かぼちゃメニュー
  → 景品画面（既存の prize）
      → 景品一覧を見る
          → 景品一覧（新規の prizeList）
              → 景品画面に戻る
                  → 景品画面（達成状況を再取得）
```

一覧への移動で参加者情報・スタンプ・ビンゴ状況を書き換えない。
既存方式に合わせて画面内のボタンで戻る。ブラウザの履歴に新しいページは追加せず、再読み込み時の動作も既存のままとする。

## 画面仕様

### 必須のデザイン制約

既存の `src/redesign/` のレイアウト・共通部品・CSSを基準に実装する。
画面の外枠、見出し、戻る操作、ボタン、カード、余白、配色、フォントは既存の仕様に合わせる。
`Frame`、`Title`、`Icon`、`rd-btn`、`rd-box` など既存の部品とスタイルを再利用する。

独自のナビゲーション、カードデザイン、装飾、アニメーション、別のUIライブラリは導入しない。
新規CSSが必要な場合も、画像のサイズ調整や文字の折り返しなど、既存レイアウトに収めるための最小限の指定に限定する。
既存UIでは対応できない要件が見つかった場合は、独自にデザインせず、実装前にユーザーへ相談する。

### 景品画面：未達成・未スタート

上から順に次を表示する。

1. 既存の見出し・ビンゴに戻る操作
2. 「まだビンゴしていません」と既存の説明
3. 既存の「ビンゴカードを見る」主ボタン
4. 新しい「景品一覧を見る」補助ボタン

達成状態の表示と主ボタンの強調を維持する。一覧へのボタンは既存の通常ボタン `rd-btn` を使う。

### 景品画面：達成済み

既存の達成表示、交換場所、スタッフへの案内を維持する。
既存のビンゴに戻るボタンの下に「景品一覧を見る」を追加する。
写真や景品カードはこの画面には並べない。

### 景品画面：読み込み中・通信エラー

既存のローダー／エラー表示の下にも一覧への入口を置く。
景品一覧自体はAPIに依存しないため、達成確認の失敗で一覧まで見られなくなることを避ける。
通信失敗を達成・未達成の確定表示に置き換えない。

### 景品一覧

上から順に次を表示する。

1. 「景品画面に戻る」ボタン
2. 「景品一覧」の見出し
3. 「今回の学園祭で用意する景品をご紹介します。」の紹介文
4. 景品カードの一覧

カードは2列配置とし、写真（任意）、景品名、紹介文（任意）を表示する。
既存のハロウィン配色、紙のカード表現、フォントを使う。長い景品名は折り返す。
写真は正方形の枠に縦横比を保って全体を表示し、元画像のサイズによって写真の高さが変わらないようにする。写真がない場合も景品名と紹介文を表示する。
画像の読み込みに失敗した場合は破損画像の表示を隠し、テキストを残す。

景品未登録時は「景品は準備中です」「一覧の公開をお楽しみに！」を表示する。
未確定の景品を実物として載せたり、交換条件や在庫数を推測して記載したりしない。

## データ設計

初回はフロントエンドの静的データで管理する。新しいAPIやDB、管理者用編集機能は作らない。

データのファイル: `src/redesign/prizeData.js`

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `id` | 必須 | 重複しない識別子。Reactの一覧キーに使用 |
| `name` | 必須 | 実際の景品名 |
| `description` | 任意 | 短い紹介文（例：コンプリート報酬） |
| `image` | 任意 | `/prizes/ファイル名.webp` 形式の画像パス |

配列の順序を表示順とする。初期値は画面を確認するための仮データ（画像なしの3件）とし、実際の景品が決まり次第差し替える。
画像は `public/prizes/` に置く（後述）。データ変更を公開するには再ビルド・再デプロイが必要。
差し替えたあとは、参加者に公開する内容だけを登録する。

### 景品画像の添付方法

画像を添付・表示できる機能は必須とし、個々の景品に画像を付けるかどうかは任意とする。
開発者が次の手順で添付する。

1. 画像を `stamp_rally_front/public/prizes/` に置く
2. そのパス（`/prizes/○○.webp`。`public` は書かない）を、該当景品の `image` に書く

`public/` のファイルはビルドでそのまま公開され、圧縮やExif削除は自動では行われない。置く前に、人の手で次を済ませる。

- 撮影日時・位置情報などのExifを消す。
- 長い辺を600px程度まで縮小する。カードの表示幅は約170pxのため、高解像度の画面でも足りる。
- WebPなどで保存し、1枚100KB以下、一覧の画像合計1MB以下を目安とする。

ファイル名には、URLの中で特別な意味を持つ記号（`#` `?` `%` など）を使わない。日本語の名前は使える。
同じ名前のまま差し替えると、来場者の端末に古い画像が残ることがあるため、差し替えるときは別の名前にする。

景品ごとに1枚の画像を登録でき、画像の追加・差し替え後も既存のカードの見た目を維持する。
画像には景品名に対応する代替テキストを付ける。
ブラウザ上でファイルを選ぶアップロード機能は現設計に含めない。画面からの添付が必要な場合は、別途要件を確認する。

## 変更したファイル

| ファイル | 変更内容 |
| --- | --- |
| `src/redesign/Prize.jsx` | 各状態の下部に一覧ボタンを追加 |

| `src/redesign/prizeList.css`（新規） | 既存UIに収めるための最小限の画像サイズ・折り返し調整。独自の見た目は定義しない |

画面切り替えに合わせたスクロールのリセットは既存の `Frame` の仕組みを利用する。
`routes.json`、GoのAPI、かぼちゃメニュー、旧画面・モックは変更対象に含めない。

## 確認項目・受け入れ条件

- 既存画面と比較し、レイアウト・見出し・ボタン・カード・配色・フォント・余白が既存仕様に準拠している。
- 独自のUI部品・ナビゲーション・装飾・アニメーション・UIライブラリを導入していない。
- 景品データに画像を添付すると該当景品に表示され、追加・差し替えができる。
- 未達成時、「ビンゴカードを見る」の直下から一覧へ移動できる。
- 達成済みでも、達成表示と交換案内を保ったまま一覧へ移動できる。
- 未スタート、通信エラー時にも一覧へ移動できる。
- 一覧の「景品画面に戻る」で景品画面に戻り、APIから達成状態を再確認する。
- 一覧の往復でスタンプ数やビンゴ達成数が変わらない。
- 景品0件・1件・複数件、写真なし・画像読込失敗、長い名前でも表示が成立する。
- 幅320px・390px・480pxで横にはみ出さず、最後のカードまでスクロールできる。
- キーボードで移動ボタンを操作でき、フォーカスが視認できる。
- かぼちゃメニューの「景品」は引き続き達成確認用の画面を開く。
- `npm run build` を実行し、変更ファイルに対してESLintを確認する。
- 実ブラウザで未達成・達成済み双方の表示と一覧の往復を確認する。

## 未決定の内容

- 実際に掲載する景品名・紹介文・写真と掲載順。
- 未確定の間は確認用の仮データで開発する。本番の景品が決まったら仮データは残さず差し替える。

## ブランチ運用

変更のないローカル `master` を起点に `feature/prize-list` を作成した。
別ブランチにコミットすれば、`master` の履歴を変更せずにレビュー・実装を進められる。
ブランチは作業フォルダや起動中の開発サーバーを別環境にするものではない。
ブランチを切り替えると同じフォルダのファイルも切り替わり、未コミットの変更は別ブランチへ持ち越される場合がある。

設計書と実装は `feature/prize-list` にコミット・pushしている。`master` へのマージと公開はまだ行っていない。
レビュー後に統合する。
リモートの最新状態との同期はこの作業では実施していないため、統合前に確認する。
